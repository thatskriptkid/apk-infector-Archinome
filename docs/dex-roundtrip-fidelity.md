# Верность round-trip `dex`: замер по корпусу 50 приложений

Векторы 9 (service code patch) и 11 (Application code patch) требуют переписать
`code_item` в **чужом** dex: добавить id'ы payload-класса, вставить
`invoke-static` в начало `<clinit>`/`<init>` и перекодировать файл целиком. Пока
не доказано, что перекодировка ничего не теряет, вердикты этих векторов на
корпусе бессмысленны: любая потеря в теле метода выглядела бы как «payload не
сработал», то есть как свойство хоста, а не как дефект инструмента.

Замер больше не заказывается отдельной задачей: он лежит в репозитории как
постоянный тест `pkg/dex/corpus_fidelity_test.go`, включается переменной
окружения (без неё `go test ./...` остаётся герметичным) и падает, если хоть
один dex перестал round-trip'иться.

## Итог

```
ARCHINOME_CORPUS_DIR=/tmp/corpus go test ./pkg/dex/ -run TestCorpusRoundTripFidelity -count=1
ok  .../pkg/dex  20.1s
corpus fidelity: 50 hosts, 79 dexes, 0 failed, 2142126 strings and 73847483 instructions compared
```

| величина | значение |
|---|---|
| хостов | 50 |
| dex-файлов (`classes*.dex`) | 79 |
| строк сверено | 2 142 126 |
| инструкций сверено | 73 847 483 |
| отказов | 0 |
| dex'ов, которые отверг наш валидатор в исходном виде | 0 |
| самый крупный файл | `rak.pixellwp/classes.dex` — 61 733 строки, 65 496 методов, 9 391 296 байт |

## Что именно сверяется

Для каждого `classes*.dex` каждого APK корпуса:

1. **Исходник проходит наш валидатор.** Копия файла пишется на диск и
   прогоняется через `Validate`. Отдельный шаг нужен, чтобы дефект валидатора не
   был записан в дефекты энкодера: до этой развязки 52 из 79 dex'ов «падали», а
   виноват был чек.
2. `Parse` → `Encode` (без единой правки — версия «патч не при чём») → `Parse`
   результата.
3. **Валидация результата** (`Validate`).
4. **По-элементное сравнение моделей**: таблицы строк/типов/прототипов/полей/
   методов (по порядку и значению), затем каждый `class_def (class_idx,
   superclass, access, interfaces, source_file, static_values)` и **каждое тело
   метода**: `registers/ins/outs`, `insns` по code unit'ам, `tries`, список
   обработчиков. Сравнение позиционное: перекодировка обязана сохранять порядок.

Внешний эталон — `dexdump` из build-tools: именно он ловит нарушения, которых не
видит наш валидатор (см. дефект 2 ниже). Прогоняется на патченном выводе
инжектора (см. `docs/corpus-50-matrix.md`).

## Найденные дефекты

Все пять — в нашем коде, все воспроизводились на реальных хостах корпуса.

### 1. Формат 35c: индекс читался из регистрового слова

**Симптом.** `encode: dex: method index 260 out of range` при **простой**
перекодировке `cn.rbc.termuc` и `io.github.muntashirakon.captiveportalcontroller`.
Числа (260, 532, 4131) не лезли в таблицу методов (126 записей) и выглядели как
регистровые наборы.

**Эталон.** `dexdump -d` печатает сырые code unit'ы и рядом свой разбор:

```
7230 e10e 6106   invoke-interface {v1, v6, v6}, Landroid/view/ViewParent;...   // из app.chompass
6e10 4200 0400   invoke-virtual {v4}, L...CPControllerTile;.isLocked:()Z      // method@0042
```

Формат 35c — `A|G|op BBBB F|E|D|C`: индекс (`0x0042`) во **второй** code unit,
регистры (`0x0004`) в **третьей**. Таблица форматов указывала `off: 4`, то есть
писатель ремапил регистровое слово как индекс метода, а настоящий индекс
оставлял неисправленным.

**Правка.** `pkg/dex/insns.go`: `0x24` и `0x6e..0x72` → `off: 2`; в комментарии
оставлен разбор из `dexdump`, чтобы «уточнение» не внесли повторно.

### 2. `class_defs` пересортированы по `class_idx` — ART это запрещает

**Симптом.** `dexdump` отвергает уже пропатченный `classes.dex` (вектор 11 на
`com.machiav3lli.fdroid`): `Invalid class definition ordering: class with type
idx: '35' defined before superclass with type idx: '55'`.

**Эталон.** У исходного `classes.dex` того же хоста: порядок `class_defs` **не**
отсортирован по `class_idx` (`25, 54, 34, 170, …`) и нарушений «superclass
раньше наследника» — 0. ART требует именно отношение «superclass определён
раньше», а не возрастание `class_idx`; d8 выдаёт классы в топологическом
порядке. Наш энкодер сортировал их по `class_idx` → **1447 нарушений**.

**Правка.** `pkg/dex/emit.go`: порядок `class_defs` берётся из исходного файла
(сдвиг таблицы типов порядок не меняет, поэтому после вставки id'ов свойство
сохраняется). В `validate.go` добавлен чек «superclass раньше» — **только
superclass**: правило про интерфейсы ART не применяет (52 из 79 dex'ов корпуса
его нарушают, и `dexdump` их принимает, проверено на `app.chompass/classes.dex`).

### 3. Валидатор строк срывался на 3-байтовых последовательностях

**Симптом.** `Validate` отвергал **исходный** dex `cn.rbc.termuc`: `string_ids
not sorted at index 2`, причём значения выглядели мусором (`"\x01\xc0\x80\x01Ā…"`).
Файл при этом ставится и работает на устройстве.

**Причина.** Сканер строк после uleb-длины шагал `p += 2` для **любого** байта
со старшим битом, хотя 3-байтовые последовательности (CJK) надо шагать на 3.
Скан уезжал на байт, читал continuation-байт как новый лид, проглатывал
терминатор и префикс длины следующей строки — отсюда и мусор в значениях.

**Правка.** `pkg/dex/validate.go`: идти до терминатора `0x00`, затем декодировать
готовым `mutf8Decode` (он же сворачивает CESU-8-пары).

### 4. Порядок строк сравнивался по байтам UTF-8, а не по code unit'ам UTF-16

**Симптом.** Тот же ложный отказ на `string_ids not sorted` — независимо от
дефекта 3, на значениях с символами вне BMP.

**Эталон.** dex требует порядок по UTF-16 (`std::u16string`), и энкодер его уже
соблюдал (`utf16Less`). Валидатор же сравнивал Go-строки оператором `<`, то есть
по байтам UTF-8 — для суррогатных пар порядок другой.

**Правка.** `pkg/dex/validate.go`: сравнение через `utf16Less` — одна функция на
энкодер и валидатор, чтобы правило не разъехалось снова.

### 5. `char` знаково расширялся

**Симптом.** `encode: dex: char value out of range` на четырёх хостах
(`ru.yourok.torrserve`, `rak.pixellwp`, `org.cryptomator.lite`,
`app.organicmaps`) — часть dex'ов не перекодировалась вообще.

**Причина.** Парсер обрабатывал `0x02 short / 0x03 char / 0x04 int / 0x06 long`
одним случаем со знаковым расширением. В dex `char` беззнаковый: значение вида
`0x8000..0xffff` разворачивалось в огромное, и энкодер справедливо отказывался
писать его как char.

**Правка.** `pkg/dex/parse.go`: `0x03` выделен отдельно и сохраняется как есть
(беззнаково). Round-trip сохраняется: `minUnsignedBytes` воспроизводит ту же
длину `value_arg`.

## Ограничения замера

- Сравниваются **модели**, а не байты файлов: перекодировка законно переставляет
  секции и пересчитывает offset'ы, побайтовое равенство тут не критерий.
- `dexdump` как внешний эталон прогоняется на выводе инжектора для нескольких
  хостов, а не для всех 79 dex'ов; для остальных внешняя проверка — установка и
  запуск на устройстве (шаг вектора).
- Установка и исполнение payload'а проверяются отдельно, вердиктами векторов:
  этот замер отвечает только за то, что правка dex ничего не портит.
- Чисто интерфейсных dex'ов с нулём тел методов в корпусе один
  (`org.cryptomator.lite/classes3.dex` — четыре интерфейса
  `Lj$/util/concurrent/Flow$*;`); «нет тел методов» для него — нормальное
  состояние, а не пропуск проверки.
